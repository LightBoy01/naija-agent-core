Oversights (things the plans missed)

OversightWhy It Matters
A2A protocol has no pricing model. If BimsGadget's customer buys through FoneZone, who earns what? The 30% referral model is for tenant onboarding, not transaction routing. Without a fee structure, no merchant will opt into cross-tenant visibility — they'd rather keep customers in their own bot.
Zynux Badge has no decay mechanism. A Gold badge earned today should degrade to Silver if delivery rate drops below 90% for 2 consecutive months. Trust scores must decay, not just accumulate. The CRON job needs both scoring AND degradation logic.
Hybrid intent classifier needs Pidgin English training data. A keyword-based classifier works for English ("check my order", "#status") but Pidgin is less structured. "Abeg where my package dey?" "I wan know wetin dey happen with my order" "Shey una don send am?" — same intent, different patterns. The classifier must be Pidgin-trained or it misses the highest-volume Nigerian messages.
Prompt caching conflicts with per-tenant system prompt updates. If a merchant updates their product catalog, the cached prompt for that tenant is stale. The Redis cache needs an invalidation trigger on catalog updates, price changes, or policy changes. Current design has no invalidation path.
AfCFTA DTP is still in negotiation. 8 annexes are not finalized. Building to the current draft means potential breaking changes when final text is adopted. The portable verification token format should be versioned and designed for upgrade, not locked to a specific DTP draft.
WhatsApp banning risk is not addressed. Both the wealth review and simulation acknowledge it. But no mitigations beyond "Cloud API route exists." Current architecture relies heavily on whatsmeow (unofficial WhatsApp Web protocol). If Meta bans unofficial clients, the entire sidecar path disappears overnight. Need a migration playbook.
